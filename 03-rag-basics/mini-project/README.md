# Мини-проект: RAG-сервис «вопросы к документации»

Выпускной проект модуля 3: FastAPI-сервис вопросов и ответов по базе знаний
«Векторики» — Qdrant + Ollama, эшелонированная оборона от галлюцинаций,
агентная переформулировка запроса, структурные логи, метрики и **тесты,
которым не нужны ни Docker, ни LLM**.

## Быстрый старт

Из папки `mini-project`, с установленными зависимостями модуля
(`pip install -r ../requirements.txt`) и запущенным Qdrant
(`docker compose up -d` из корня модуля):

```bash
python -m app.ingest
```

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```bash
curl -X POST http://127.0.0.1:8000/ask -H "Content-Type: application/json" -d "{\"question\": \"Сколько дней отпуска положено в году?\"}"
```

Семантический бэкенд — одной переменной окружения (отдельная коллекция
`miniproject_kb_e5` создаётся сама; нужен `sentence-transformers`):

```bash
EMB_BACKEND=e5 python -m app.ingest
```

```bash
EMB_BACKEND=e5 uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## Тесты — без Docker и без Ollama

```bash
pytest
```

47 тестов за доли секунды. Секрет — инъекция зависимостей: `RagService`
и приложение получают снаружи три async-функции (`search`, `generate`,
`health`), за которыми в проде живут Qdrant и Ollama, а в тестах — фейки
из `tests/conftest.py`. Фейковый `generate` различает роль вызова по
системному промпту (генерация / self-check / переформулировка) и считает
каждую отдельно — поэтому тесты проверяют и НЕ-вызовы: LLM не трогается
при отбитом вводе, retry не случается при чистом self-check,
переформулировка не зовётся при пройденном пороге.

## Устройство

```
app/
├── config.py     # настройки из env; суффикс бэкенда в имени коллекции (урок 3.2)
├── kb.py         # документы + абзацный чанкинг с заголовками (уроки 2.5-2.6)
├── embedder.py   # TF-IDF и e5 за одним интерфейсом + фабрика (уроки 2.5, 3.2)
├── sanitizer.py  # clean/suspicious/rejected + нейтрализация </context> (урок 3.7)
├── logs.py       # structlog: JSONL, request_id, вопрос - только хэшем (урок 3.7)
├── rag.py        # RagService: конвейер с рубежами 2-4 и агентным retry
├── metrics.py    # скользящее окно, p50/p95/p99, счётчики вердиктов (урок 3.7)
├── ingest.py     # батч-индексация: python -m app.ingest (урок 3.2)
└── main.py       # FastAPI: /healthz /search /ask /metrics; Deps для подмены
tests/            # фейки и 47 тестов: embedder, sanitizer, config, rag, логи, API
```

Путь запроса `/ask`: Pydantic-валидация формы → санитайзер (урок 3.7) →
поиск → порог релевантности; при промахе — агентный retry: переформулировка
запроса моделью и один повторный поиск (урок 3.5) → генерация с промптом v3
и требованием цитаты (уроки 3.3–3.4) → механика цитат: ссылки `[i]` +
`<quote>` подстрокой контекста → self-check судьёй, при провале один retry
с t=0.3 → канонизация отказа с подсказкой тем → метрики → ответ с вердиктом,
паспортом `checks` и счётчиком `llm_calls`.

Вердикты: `ok` | `refused_by_threshold` | `refused_by_model` |
`refused_after_checks` (ответ не прошёл рубежи и после retry) |
`rejected_input`.

Логи — JSONL в `logs/rag.jsonl`: `request_id` привязывается на границе
запроса через contextvars и сшивает события (`request_received` →
`retrieval_done` → ... → `answer_returned`); текст вопроса в лог не
попадает никогда — только длина и хэш.

## Конфигурация (переменные окружения)

| переменная | по умолчанию |
|---|---|
| `QDRANT_URL` | `http://127.0.0.1:6333` |
| `OLLAMA_URL` | `http://127.0.0.1:11434` |
| `LLM_MODEL` | `qwen2.5:3b` |
| `LLM_THINK` | `0` — thinking-модели (qwen3.5+) не рассуждают перед ответом (1 — включить) |
| `NUM_CTX` | `8192` — контекст на один запрос (system + чанки + вопрос + ответ); дефолт сервера 4096 для RAG впритык |
| `EMB_BACKEND` | `tfidf` (или `e5` — encode уезжает в `anyio.to_thread`) |
| `RAG_COLLECTION` | `miniproject_kb` / `miniproject_kb_e5` — по бэкенду |
| `DATA_DIR` | `../data` (14 документов «Векторики») |
| `LOG_PATH` | `logs/rag.jsonl` |
| `SCORE_THRESHOLD` | `0.10` — калиброван под TF-IDF (урок 3.4); под e5 подберите свой |
| `GUARDRAILS` | `1` — рубежи 2–4: цитаты + self-check + retry (0 — доверять модели) |
| `AGENT_MODE` | `1` — переформулировка при промахе порога (0 — отказ сразу) |

Всюду `127.0.0.1`, не `localhost` — грабля Windows из урока 3.2.
Рубежи стоят вызовов LLM (happy path — 2 вызова вместо 1, отказ порога
при агентном режиме — 1 вместо 0): выключатели — это решение эксплуатации,
см. расчёт цены обороны в уроке 3.4.

## Идеи для прокачки (упражнения урока 3.8)

1. Стриминг `/ask/stream` (SSE, урок 3.2) — и как подружить его с self-check.
2. Порог под бэкенд: откалибруйте `SCORE_THRESHOLD` для e5 по golden-датасету.
3. Эскалация вместо отказа: при `refused_after_checks` — повтор с `top_k + 2`.
4. Дежурный робот: `check_alerts` по `/metrics` (урок 3.7).
