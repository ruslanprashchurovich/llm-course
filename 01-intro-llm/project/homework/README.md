# llm-hw — решение «Заданий для прокачки» урока 1.8

Это эталонное решение домашнего задания к финальному проекту модуля 1. Базовая
утилита ([`../llm_cli.py`](../llm_cli.py)) — чистый старт на `argparse`, который
предлагается написать самому. Здесь она доведена до всех пяти доработок из урока
1.8 и в качестве бонуса переписана на [typer](https://typer.tiangolo.com/) с
цветным выводом на [rich](https://rich.readthedocs.io/).

> Сначала попробуйте сами — подглядывать в готовое интереснее, когда уже упёрлись.

## Команды и доработки

### 1. `--stats` — расход токенов и облачная цена

Флаг есть у каждой команды, которая обращается к модели. Он показывает реальные
счётчики токенов и во что тот же запрос обошёлся бы в облаке — по прайсу из урока 1.3.

```bash
llm ask "Объясни, что такое замыкание" --stats
llm ask "Один факт про Python" --no-stream --stats
```

Пример прогона (`llm ask "..." --stats`) — ответ уходит в stdout, таблица в stderr:

```text
Париж
   расход токенов: 62 in + 4 out = 66 токенов  ·  локально бесплатно
┌───────────────────────────┬────────────┬───────────────────┐
│ если бы облако (урок 1.3)  │ $ / запрос │ ₽ / 1000 запросов │
├───────────────────────────┼────────────┼───────────────────┤
│ gpt-4o-mini               │  $0.000012 │            1.05 ₽ │
│ deepseek-chat             │  $0.000021 │            1.90 ₽ │
│ claude-haiku              │  $0.000066 │            5.90 ₽ │
│ gpt-4o                    │  $0.000195 │           17.55 ₽ │
│ claude-sonnet             │  $0.000246 │           22.14 ₽ │
└───────────────────────────┴────────────┴───────────────────┘
```

(Число output-токенов слегка гуляет от запуска к запуску — генерация недетерминирована.)

Два важных инженерных решения:

- **Стриминг + usage.** По умолчанию при `stream=True` счётчики не приходят — их
  включает `stream_options={"include_usage": True}`. Ollama кладёт `usage` в
  финальный служебный чанк (у него `choices` пустой). См. [`llmio.py`](llm_hw/llmio.py).
- **Статистика идёт в `stderr`.** Поэтому `--stats` не ломает пайпы: в stdout
  остаётся только ответ модели, а таблица токенов печатается отдельным потоком.

### 2. `commit` — сообщение коммита из диффа

```bash
git add .
git diff --staged | llm commit
# сразу закоммитить:
git diff --staged | llm commit | git commit -F -
```

Если пайпа нет, утилита сама выполнит `git diff --staged`. System-роль задаёт
формат (Conventional Commits, повелительное наклонение, ≤ 72 символа), а few-shot
из трёх пар «дифф → сообщение» закрепляет стиль. Дифф режется до `MAX_DIFF_CHARS`,
чтобы не переполнить контекст (урок 1.1).

### 3. `translate` — перевод с глоссарием

```bash
llm translate "Create a ticket for the failed deploy" --to ru
echo "Влей пул-реквест после ревью" | llm translate --to en
```

Глоссарий в системном промпте + few-shot примеры фиксируют «наши» варианты
терминов: `ticket → тикет` (не «билет»), `merge → мёрж`, `deploy → деплой`.
Направление задаётся `--to ru|en`, few-shot подбирается под направление.

### 4. `chat` — память между запусками

```bash
llm chat            # продолжает прошлый диалог
llm chat --fresh    # начать с чистого листа
```

История хранится в `~/.llm_history.json` и загружается при старте — диалог
переживает закрытие утилиты. При загрузке и сохранении применяется `MAX_HISTORY`
(последние 12 сообщений), чтобы файл не рос и контекст не переполнялся. Команда
`/clear` забывает контекст и удаляет файл.

### 5. Упаковка

`pyproject.toml` объявляет entry point `llm = "llm_hw.cli:main"`. Console-script
требует вызываемую функцию, поэтому точка входа — обёртка `main()` (в ней же —
единственная дружелюбная обработка `APIConnectionError`), а не сам объект `app`.
