# Релизы и версионирование

Как нумеруются версии и что входит в релизный процесс.

## Версии

Версии следуют SemVer: `vMAJOR.MINOR.PATCH`. MINOR повышается в плановом
недельном релизе, PATCH — в хотфиксах, MAJOR — при ломающих изменениях
публичного API (согласуется с владельцами клиентов заранее). Тег ставится
на коммит в `main` после стабилизации staging.

## Релизный цикл

Релизный поезд отправляется раз в неделю, по вторникам. Понедельник — фриз:
в релизную ветку попадают только фиксы стабилизации. Релиз-менеджер (роль
ротируется по команде) собирает changelog из заголовков MR — ещё одна причина
писать их по Conventional Commits.

## Changelog

Changelog ведётся в `CHANGELOG.md` и публикуется в #releases при каждом теге.
Формат записи: версия, дата, разделы Added / Changed / Fixed / Security.
Пользовательские формулировки, без внутреннего жаргона: changelog читают
и поддержка, и менеджеры.

## Feature-флаги

Незавершённая функциональность уезжает в прод под feature-флагом (сервис
Unleash), а не живёт в долгоживущей ветке. Флаг обязан иметь владельца и дату
уборки: мёртвые флаги — это тех-долг, их чистка входит в определение Done.
