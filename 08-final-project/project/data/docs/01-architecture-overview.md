# Обзор архитектуры платформы

Документ описывает верхнеуровневую архитектуру платформы «Векторика» для новых
инженеров. Детали по каждому сервису — в документации команд.

## Состав системы

Платформа состоит из четырёх основных частей: веб-приложение (SPA на React),
API-гейтвей, набор бэкенд-сервисов на Python (FastAPI) и фоновые воркеры.
Синхронное общение между сервисами — HTTP/JSON через внутренний балансировщик,
асинхронное — через очередь RabbitMQ (обменник `vectorika.events`).

## Хранилища

Основная база — PostgreSQL 16, по одной базе на сервис (правило «сервис не лезет
в чужую базу напрямую» — только через API владельца). Кэш и короткоживущие данные —
Redis. Файлы и выгрузки — S3-совместимое хранилище MinIO. Поиск по документам —
Qdrant.

## Окружения

Окружений три: dev (обновляется на каждый коммит в main), staging (стабилизация
перед релизом, копия прода по конфигурации) и production. Доступ к production
имеют только дежурные инженеры и релиз-менеджер. Конфигурация окружений живёт
в репозитории `infra` (Terraform + Ansible).

## Принципы

Мы предпочитаем скучные технологии: PostgreSQL вместо модной NoSQL, HTTP вместо
кастомных протоколов, монорепозиторий с чёткими границами модулей. Новая
технология попадает в стек только через RFC с обсуждением и пилот на одном
некритичном сервисе.
