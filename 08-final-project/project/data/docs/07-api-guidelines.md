# Гайдлайны проектирования API

Правила для всех внутренних и внешних HTTP API «Векторики».

## Общие принципы

API — REST поверх HTTP/JSON. Версия — в пути: `/v1/...`; ломающие изменения
возможны только в новой версии, старая живёт минимум полгода после объявления
о устаревании. Имена полей — snake_case. Даты и время — ISO 8601 в UTC
(`2026-08-27T12:00:00Z`), деньги — целые числа в минорных единицах (копейках).

## Пагинация и фильтры

Списки отдаются страницами: параметры `limit` (по умолчанию 20, максимум 100)
и `offset`. В ответе обязательны `items` и `total`. Фильтры — обычные
query-параметры; сложные фильтры (диапазоны, множества) обсуждаются с
архитектором до реализации.

## Ошибки

Формат ошибок — RFC 7807 (application/problem+json): поля `type`, `title`,
`status`, `detail`. Валидационные ошибки — 422 со списком нарушений по полям.
Правило кодов: 4xx — проблема на стороне клиента (чинит клиент), 5xx — наша
(чинит сервис). Никогда не возвращаем 200 с текстом ошибки в теле.

## Идемпотентность и таймауты

Все небезопасные операции, которые клиент может повторить (оплаты, создание
заказов), принимают заголовок `Idempotency-Key`. Серверные таймауты явные:
gateway режет запросы дольше 30 секунд — длинные операции оформляются как
асинхронные задачи со статус-эндпоинтом.
