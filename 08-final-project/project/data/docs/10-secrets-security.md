# Секреты и базовая безопасность

Как мы храним секреты и что считается инцидентом безопасности.

## Хранение секретов

Все секреты приложений (API-ключи, токены, строки подключения к базам) хранятся
в HashiCorp Vault и попадают в приложение через переменные окружения при
деплое. В git секретам не место: pre-commit hook с detect-secrets и сканер
в CI блокируют MR при обнаружении. Файл `.env.local` для локальной разработки
выдаётся из Vault и не коммитится.

## Коммит секрета

Коммит секрета в git — инцидент безопасности уровня SEV2, даже если репозиторий
внутренний и «никто не видел». Порядок действий: немедленно сообщить в
#security, ротировать секрет (старый отзывается в течение часа), затем вычистить
историю. Ротация важнее вычистки: считаем, что утёкший секрет уже скомпрометирован.

## Доступы

Доступы выдаются по принципу минимально необходимого и через группы, а не
персонально. Доступ к проду — только у дежурных и SRE, и каждый вход логируется.
Ревизия доступов — раз в квартал; уволившиеся сотрудники отключаются в день
увольнения автоматически через SCIM.

## Зависимости

Уязвимости зависимостей отслеживает Dependabot; критические (CVSS 9+)
закрываются в течение 48 часов, высокие — в недельный релиз. Обновление
зависимостей — обычный MR со всеми тестами, без «быстренько на проде».
