# ADR-0003. Reranker: включаемый cross-encoder

Дата: 2026-08. Статус: принято.

## Контекст

Bi-encoder иногда путает близкие по теме фрагменты (деплой vs откат vs релиз).
Cross-encoder читает пару «запрос+фрагмент» целиком и ранжирует точнее, но
стоит O(кандидатов) прогонов модели на каждый запрос.

## Решение

Двухступенчатая схема: ANN отбирает fetch_k=20 кандидатов, cross-encoder
(`mmarco-mMiniLMv2-L12-H384-v1`) пересортировывает, отдаём top_k=5. Reranker
ВЫКЛЮЧАЕМ одной переменной (APP_RERANKER_ENABLED) и на каждый запрос
(use_reranker) - для честных A/B-сравнений и деградации под нагрузкой.

## Последствия

+~500 МБ модель и +десятки/сотни мс на запрос при включённом reranker;
шкалы score (косинус) и rerank_score (логит) разные и не сравниваются между
собой - это зафиксировано в контракте API.
