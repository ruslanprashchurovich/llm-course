# ADR-0004. История диалогов: SQLite (aiosqlite)

Дата: 2026-08. Статус: принято.

## Контекст

Нужно сохранять пары вопрос-ответ с источниками: для отладки качества,
разбора жалоб и будущего golden-набора (курс, урок 3.3). Сервис внутренний,
единицы-десятки пользователей.

## Решение

SQLite через aiosqlite: нулевая эксплуатация, один файл, легко бэкапится,
async-интерфейс не блокирует event loop. Список источников храним JSON-строкой
в колонке - отдельная таблица связей для v1 избыточна.

## Альтернативы

- PostgreSQL: правильный ответ «по-взрослому», но это +процесс, +миграции,
  +секреты ради таблицы с сотней строк в неделю.
- Логи вместо БД: история нужна структурированной и запрашиваемой (/api/history),
  логи для этого неудобны.

## Последствия

Одновременная запись ограничена природой SQLite - для нашего трафика не
проблема. Путь миграции: интерфейс HistoryRepository уже async и узкий,
замена на PostgreSQL не тронет роутеры (см. урок 6 модуля - «компромиссы»).
