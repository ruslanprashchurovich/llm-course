# ollama-proxy — финальная практика модуля 5

FastAPI-прокси перед Ollama, который добавляет демону всё, чего ему не хватает
для продакшена. У Ollama нет аутентификации, нет потолков на запрос, нет метрик
по клиентам — прокси становится единственным входом и решает это один раз для всех.

```
клиенты --(X-API-Token)--> ollama-proxy :8005 --> Ollama :11434 --> модель
                            │ auth (401)                       ├ основная  qwen2.5:3b
                            │ лимит на токен (429 + Retry-After) └ запасная  (PROXY_FALLBACK_MODEL)
                            │ потолок num_predict
                            │ семафор + queue_ms
                            │ retry по матрице (503/connect — да, ReadTimeout — нет)
                            │ маршрутизация: healthz решает, /generate исполняет
                            │ метрики: окно ток/с по моделям, Prometheus /metrics
                            └ healthz: версия, доля GPU, дрейф digest, деградация
```

Три уровня практики урока 5.7 реализованы здесь же (эталон — в проекте, как
`kb_search` в модуле 2): `/models`, лимиты на токен, две модели с деградацией.
Сначала попробуйте сами, потом сверяйтесь.

## Что откуда взято

| Решение в коде | Урок |
|---|---|
| `127.0.0.1` вместо localhost, connect/read таймауты раздельно | 5.3 |
| retry с джиттером по матрице; ReadTimeout без повторов → 504 | 5.3 |
| аутентификация по токену (у Ollama её нет) | 5.3 |
| лимит N запросов/мин на токен: скользящее окно, честный `Retry-After` | 5.7 (практика), 5.3 |
| потолок `num_predict` на сервере, клиенту не доверяем | 5.6 |
| семафор конкуренции + честный `queue_ms`; быстрый 503 из очереди | 3.2, 5.6 |
| окно скоростей p50/p95 с каждого ответа, холодные старты — по моделям | 5.5 |
| healthz: L1/L2 без деструктивной пробы; доля модели в VRAM | 5.5 |
| проверка digest модели при старте → `degraded` при дрейфе | 5.6 |
| `/models`: инвентарь диска Ollama с размерами и digest | 5.6, 5.7 (практика) |
| деградация на запасную модель: GPU-доля или p50 < ½ baseline; канарейки для возврата | 5.5, 5.6, 5.7 (капстоун) |
| DI: `create_app(client=..., clock=...)` + тесты на фейках со счётчиками, без sleep | 3.8, 5.5 |
| retry-матрица протестирована через `httpx.MockTransport` — без сети | 5.7 |

## Запуск

```powershell
cd ollama-proxy
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8005
```

Требуется запущенная Ollama с моделью `qwen2.5:3b` (уроки 1.5, 5.3). Без неё
прокси тоже работает — честно отвечает `down`/502 (это проверено тестами и уроком).
Для деградации нужна и запасная: `ollama pull qwen2.5:1.5b` плюс
`PROXY_FALLBACK_MODEL=qwen2.5:1.5b`.

## Эндпоинты

```bash
# здоровье (без токена): статус ok|degraded|down + доля GPU + p50 + решение роутера
curl http://127.0.0.1:8005/healthz

# инвентарь диска Ollama: имя, размер, digest, квантизация, роль (primary/fallback)
curl -H "X-API-Token: dev-token" http://127.0.0.1:8005/models

# генерация (токен обязателен; N запросов в минуту на токен, иначе 429 + Retry-After)
curl -X POST http://127.0.0.1:8005/generate \
  -H "Content-Type: application/json" -H "X-API-Token: dev-token" \
  -d '{"prompt": "Что такое GIL?", "num_predict": 100, "temperature": 0.1}'

# метрики Prometheus
curl http://127.0.0.1:8005/metrics
```

Ответ `/generate` возвращает и телеметрию: `tokens_per_second`, `load_seconds`
(холодный старт виден сразу), `queue_ms` (сколько запрос ждал очередь),
а также `route` (`primary` / `fallback` / `canary`) и `degraded_to` — имя запасной
модели, если ответ пришёл от неё. Успешные ответы несут заголовки
`X-RateLimit-Limit` и `X-RateLimit-Remaining`.

### Как работает деградация

1. `/healthz` смотрит на **основную** модель: долю в VRAM из `/api/ps` и p50 её окна
   скоростей. Доля ниже `PROXY_DEGRADE_GPU_SHARE` или p50 ниже
   `PROXY_DEGRADE_P50_RATIO × baseline` — статус `degraded`, роутер переключается.
2. Новые `/generate` идут в запасную модель с `degraded_to` в ответе. Каждый пятый —
   **канарейка** в основную: иначе её окно не обновится и вернуться будет нельзя.
3. Следующий `/healthz` с нормальной долей GPU и p50 (по трём и более свежим
   канарейкам) возвращает трафик на основную.

Решения принимает healthz, а не каждый запрос: за `/api/ps` ходим по расписанию
пробника (watchdog урока 5.5), а не на каждом `/generate`. Baseline задаётся
`PROXY_BASELINE_TPS` (замер урока 5.5) или выучивается по первым ответам здоровой
основной. Гистерезис и for-duration против дребезга — упражнение.

## Конфигурация (переменные окружения)

| Переменная | Дефолт | Зачем |
|---|---|---|
| `OLLAMA_URL` | `http://127.0.0.1:11434` | адрес демона |
| `PROXY_MODEL` | `qwen2.5:3b` | основная модель |
| `PROXY_FALLBACK_MODEL` | — | запасная модель; пусто = только статус `degraded`, без переключения |
| `PROXY_BASELINE_TPS` | `0` (выучить) | p50 ток/с здоровой основной для порога деградации |
| `PROXY_DEGRADE_GPU_SHARE` | `0.9` | доля основной в VRAM ниже порога = «съехала с GPU» |
| `PROXY_DEGRADE_P50_RATIO` | `0.5` | p50 ниже этой доли baseline = деградация |
| `PROXY_TOKENS` | `dev-token` | токены через запятую; пусто = auth выключена |
| `PROXY_RATE_LIMIT_PER_MIN` | `60` | запросов к `/generate` на токен за скользящие 60 с; `0` = без лимита |
| `PROXY_NUM_PREDICT_CAP` | `512` | потолок генерации на запрос |
| `PROXY_MAX_CONCURRENT` | `1` | слоты к модели (CPU: не увеличивать — урок 5.3) |
| `PROXY_QUEUE_TIMEOUT_S` | `30` | ожидание слота, дальше 503 |
| `PROXY_READ_TIMEOUT_S` | `180` | потолок на генерацию |
| `PROXY_RETRIES` | `2` | повторы по матрице |
| `PROXY_PINNED_DIGEST` | — | зафиксированный digest модели (урок 5.6) |

## Тесты

```bash
pytest
```

42 теста, все на фейках, `httpx.MockTransport` и управляемых часах — Ollama, модель
и `sleep` не нужны. Фейки считают вызовы, поэтому тесты проверяют и **НЕ**-вызовы:
после ReadTimeout прокси не пошёл в Ollama второй раз, отбитый 429 до Ollama
не дошёл, чужой токен получает 401 и ничей лимит не тратит. Переключение на
запасную модель и обратно проверено на фейке в обе стороны: по доле GPU
и по p50 с канарейками.

## Docker

`docker compose up -d --build` поднимает Ollama и прокси одной командой
(порт Ollama наружу не публикуется — вход только через прокси).
Файлы — рабочая заготовка, в уроке compose не прогонялся.
