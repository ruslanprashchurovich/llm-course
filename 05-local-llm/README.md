# Модуль 5. Локальные LLM: запуск без облака и без GPU

Часть курса «LLM для Python-разработчиков: от RAG до агентов».

Этот модуль — о том, как запускать большие языковые модели (LLM) **на своём железе**: без облачных API, без GPU и без бюджета. Всё работает на обычном CPU под Windows 11 (и Linux/macOS тоже). Мы честно разбираем, когда это оправдано, какие модели реально влезут в вашу RAM, с какой скоростью они будут работать, и как превратить «запустил на ноутбуке» в надёжный сервис с мониторингом.

## Цели модуля

После прохождения вы сможете:

- Обоснованно решать, когда нужна локальная LLM, а когда честнее взять API (матрица принятия решения).
- Выбирать модель и квантизацию под свою RAM и свои задачи, а не по хайпу — с собственным мини-бенчмарком.
- Разворачивать Ollama как надёжный сервис: служба Windows (NSSM), systemd, Docker; keep_alive, параллелизм, очереди.
- Делать прямой inference через `llama-cpp-python` и понимать, когда он лучше Ollama.
- Мониторить локальную LLM: health-checks, токены/сек, память, деградация, алерты.
- Диагностировать типовые проблемы: OOM, медленная генерация, зависшие запросы, конкуренция, версионирование моделей.
- Собрать production-обёртку: FastAPI-прокси перед Ollama с retry, метриками и health-checks (финальная практика).

## Что понадобится

- **Windows 11 / Linux / macOS**, Python **3.13** (подойдёт и 3.11+).
- **RAM**: минимум 8 ГБ (для моделей 1B–3B), комфортно — 16 ГБ (для 7–8B).
- **Диск**: ~10 ГБ свободных под модели.
- **GPU НЕ нужен.** Платные API НЕ нужны.
- Интернет — только для `pip install` и `ollama pull`.
- Опционально: Docker Desktop (для docker-варианта Ollama в уроках 3 и 7).

## Подготовка окружения

### 1. Виртуальное окружение и зависимости

PowerShell (Windows):

```powershell

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

bash (Linux/macOS/WSL):

```bash
cd ~/ml_projects/llm-course/05-local-llm
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

> Если `Activate.ps1` блокируется политикой выполнения: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` (один раз, из PowerShell).

### 2. Установка Ollama

- **Windows**: скачайте установщик с <https://ollama.com/download> или `winget install Ollama.Ollama`. После установки демон доступен на `http://127.0.0.1:11434`.
- **Linux**: `curl -fsSL https://ollama.com/install.sh | sh` (создаст systemd-службу).
- **Docker-вариант**: `docker compose up -d` в папке модуля (см. `docker-compose.yml`).

Проверка: `ollama --version`, затем `curl http://127.0.0.1:11434/api/version` (PowerShell: `Invoke-RestMethod http://127.0.0.1:11434/api/version`). В коде используйте именно 127.0.0.1, а не localhost, — почему, объясняет урок 3.

### 3. Модели для уроков

Если вы шли по курсу с модуля 1, обе нужные модели уже скачаны:

```bash
ollama pull qwen2.5:3b        # ~2.0 ГБ — рабочая модель курса (урок 1.5)
ollama pull qwen2.5:0.5b-base # ~0.4 ГБ — base-модель из урока 1.6 (нужна в уроке 2)
```

Уроку 4 отдельный GGUF-файл не нужен: llama-cpp-python читает модель прямо
из блоба в хранилище Ollama (как его найти — в самом уроке).

Опционально:

```bash
ollama pull qwen2.5:1.5b      # ~1.0 ГБ — «сосед по размеру» для бенчмарка (упражнение урока 2)
ollama pull qwen2.5:7b        # ~4.7 ГБ — если RAM >= 16 ГБ и хочется сравнить классы
```

Команды одинаковы в PowerShell и bash. Если `registry.ollama.ai` у вас блокируется,
работает запасной путь через Hugging Face (см. урок 1.5):
`ollama pull huggingface.co/<репозиторий>:<квантизация>`.

### 4. Установка llama-cpp-python (для урока 4)

Пакет **закомментирован** в `requirements.txt`, потому что на Windows его установка требует внимания:

1. **Попробуйте готовое CPU-колесо** (собранный бинарник, без компиляции; у нас на Python 3.13 встало именно оно — llama-cpp-python 0.3.x):

   ```powershell
   pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
   ```

2. Если для Python 3.13 колеса нет — **сборка из исходников**: установите [Visual Studio Build Tools 2022](https://visualstudio.microsoft.com/visual-cpp-build-tools/) (workload «Разработка классических приложений на C++») и CMake, затем `pip install llama-cpp-python`. Сборка на CPU занимает 10–20 минут.
3. Запасной вариант — отдельный venv на Python 3.12 только для урока 4 (для него готовые колёса есть почти всегда), либо пакет `llama-cpp-python` из conda-forge.

На Linux обычно достаточно `pip install llama-cpp-python` (нужны `gcc`/`cmake`: `sudo apt install build-essential cmake`).

## Честные ориентиры (подробно — в уроке 2)

| Модель (Q4_K_M) | Файл | RAM в работе (4k контекст) | Скорость на CPU* |
|---|---|---|---|
| 1B | ~0.8 ГБ | ~1.5–2 ГБ | 20–80 ток/с |
| 3B | ~2.0 ГБ | ~3–3.5 ГБ | 8–35 ток/с |
| 7–8B | ~4.7–4.9 ГБ | ~6–7 ГБ | 4–16 ток/с |

\* Диапазон: от троттлящего ноутбука до десктопа с DDR5. Генерация на CPU упирается
в пропускную способность памяти, а не в ядра; живой замер урока 2 на ноутбуке
с DDR5-4800 дал для 3B 15–17 ток/с (~40% от пиковой полосы).

## FAQ

**Нужен ли GPU?** Нет. Весь модуль рассчитан на CPU. GPU ускоряет генерацию в разы (живой замер урока 2: ~4 раза для 3B на ноутбучной карте; десктопные — на порядок), но принципы те же.

**Всё ли бесплатно?** Да: Ollama, llama.cpp, модели с открытыми весами, Prometheus-клиент. Платные API нигде не требуются.

**Ноутбук с 8 ГБ RAM — хватит?** Для уроков — да: `qwen2.5:3b` в работе занимает ~3 ГБ. 7B-модели требуют ~6–7 ГБ свободной RAM — закройте браузер или пропустите эти примеры.

**Бенчмарк урока 2 даёт 0%, у всех задач done=length и пустой ответ?** Вы гоняете thinking-модель (qwen3.5+): без явного `think: false` она тратит весь `num_predict` на рассуждения в поле `message.thinking`, а `content` остаётся пустым. Поле кладётся на верхний уровень запроса, не в `options` (там оно молча игнорируется). `scripts/bench.py` и раннер ноутбука уже шлют его; разбор с живой таблицей — частая ошибка 6 урока 2.

**Могу я проходить модуль без запущенной Ollama?** Теория и часть кода — да: все ячейки, которым нужен сервер, проверяют его доступность и аккуратно пропускаются. Но практическая ценность — именно в запуске.
