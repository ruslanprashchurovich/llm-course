## А

**Агент** — LLM в цикле «модель решает → инструмент выполняет → результат возвращается модели», с лимитом шагов. В отличие от конвейера, маршрут выбирает сама модель. *(урок 3.5)* См. также: Инструмент, Оркестратор, Мульти-агентная система.

**Адаптер (LoRA-)** — Пара маленьких матриц A и B, обучаемая поверх замороженной модели; вся «разница» дообучения в файле на десятки МБ. Привязан к точным весам базовой модели. *(урок 6.1, 6.3)* См. также: LoRA, Digest.

**Алерт** — Автоматическое оповещение при выходе метрики за порог. Правильный алерт имеет длительность срабатывания (for-duration: OK → PENDING → FIRING) и runbook. *(урок 5.5, 4.3)* См. также: Наблюдаемость, Перцентиль.

## Б

**База знаний** — Корпус документов, по которому ищет RAG-система. Качество ответов ограничено качеством базы: мусор на входе — мусор на выходе. *(урок 2.5, 4.1)* См. также: Чанк, Индексация.

**Батчинг** — Обработка данных пачками (например, эмбеддинги по 32 текста за вызов) — быстрее поштучной за счёт векторизации вычислений. *(урок 2.4, 8.2)*

## В

**Векторная база данных** — Хранилище векторов с быстрым поиском ближайших (ANN-индексы вместо полного перебора) и метаданными-фильтрами. В курсе: Chroma и Qdrant. *(урок 2.2–2.4)* См. также: ANN, HNSW, Payload.

## Г

**Галлюцинация** — Уверенное утверждение модели, не подкреплённое ни контекстом, ни фактами. На GPU при temperature 0 бывает «мерцающей» — воспроизводится не в каждом прогоне. *(урок 3.3, 3.4)* См. также: Grounding, Отказ.

**Гибридный поиск** — Совмещение семантического (эмбеддинги) и лексического (BM25) поиска со слиянием результатов, обычно через RRF. Закрывает слабость векторов к точным строкам. *(урок 4.4)* См. также: BM25, RRF.

## Д

**Дежурство здравого смысла** — Неформальное правило курса: перед сложным решением проверить дешёвую ступень лестницы — промпт → RAG → грамматика → дообучение → агенты. *(урок 6.1, 7.1)*

**Диверсификация выдачи** — Ограничение «не более N чанков с одного документа» в результатах поиска, чтобы топ не заняли соседние куски одного файла. *(урок 2.5)* См. также: Reranking.

**Дистрибутивная гипотеза** — «Слово определяется компанией, в которой встречается»: слова из похожих контекстов близки по смыслу. Фундамент эмбеддингов. *(урок 2.1)* См. также: Эмбеддинг.

**Дообучение (fine-tuning)** — Продолжение обучения модели на своих данных. В курсе — только параметро-эффективное (LoRA/QLoRA); полное дообучение 3B требует ~46 ГБ памяти. *(урок 6.1)* См. также: LoRA, QLoRA.

## З

**Замороженные веса** — Параметры, не участвующие в обучении (градиенты не считаются). В LoRA заморожена вся базовая модель — учится только адаптер. *(урок 6.1)* См. также: Адаптер (LoRA-).

## И

**Идемпотентность** — Свойство операции давать тот же результат при повторении. В курсе: переиндексация с детерминированными uuid5-ID обновляет точки, а не плодит дубли. *(урок 2.4, 8.2)* См. также: uuid5, Upsert.

**Индексация** — Превращение документов в точки векторной БД: чанкинг → эмбеддинги → upsert. Оформляется скриптом (правами администратора), а не эндпоинтом. *(урок 2.4, 8.2)* См. также: Чанк, Батчинг.

**Инструмент (tool)** — Функция, которую агент может вызвать: модель генерирует JSON вызова, ваш код исполняет и возвращает результат текстом. Описание инструмента — тоже промпт. *(урок 3.5)* См. также: Function calling, Агент.

**Инъекция промпта** — См. Prompt injection. *(урок 1.2, 4.2)*

## К

**Канарейка (canary)** — Небольшой контрольный прогон (бенчмарк, golden-вопросы) после обновления модели или индекса — до того, как изменение увидят пользователи. *(урок 5.6, 8.6)* См. также: Golden-набор, Digest.

**Кардинальность меток** — Число уникальных значений метки в метрике. Метка с user_id порождает миллионы временных рядов и убивает Prometheus — в метках только ограниченные множества. *(урок 4.3)* См. также: Наблюдаемость.

**Катастрофическое забывание** — Потеря моделью общих навыков при дообучении на узких данных. LoRA защищена конструктивно: базовые веса заморожены, адаптер можно снять. *(урок 6.1)* См. также: Протечка стиля.

**Квантизация** — Сжатие весов модели в меньшую разрядность (fp16 → 4 бита): в разы меньше памяти ценой небольшой потери точности. Q4_K_M — рабочая лошадка курса. *(урок 5.2)* См. также: GGUF, QLoRA.

**Контекстное окно** — Максимум токенов, который модель обрабатывает за раз (промпт + ответ). Превышение — тихая обрезка или ошибка; размер задаёт num_ctx. *(урок 1.5, 5.6)* См. также: KV-кэш, Токен.

**Контекстные заголовки** — Приписывание заголовка документа к тексту чанка перед индексацией: индексируем обогащённый текст, показываем оригинал. *(урок 2.6)* См. также: Чанк.

**Косинусная близость** — Мера сходства векторов по углу (−1..1, для нормированных эмбеддингов практически 0..1). У плотных моделей рабочая полоса узкая: сортировать можно, судить об «уверенности» — нет. *(урок 2.1, 8.3)* См. также: Эмбеддинг.

## Л

**Лестница приёмов** — Порядок эскалации решений: инструкция → few-shot → RAG → жёсткие форматы → дообучение → команда агентов. Каждая ступень дороже предыдущей — подниматься только по показаниям eval. *(урок 1.7, 6.1, 7.1)*

## М

**Мульти-агентная система** — Несколько LLM-вызовов с разными ролями плюс оркестратор, передающий между ними работу. Паттерны: pipeline, supervisor, debate. Цена — ×N вызовов и латентность. *(урок 7.1–7.4)* См. также: Оркестратор, Роль.

**Мультитенантность** — Изоляция данных разных клиентов/команд в одной системе. В векторном поиске — обязательный pre-filter по владельцу в каждом запросе. *(урок 4.5)* См. также: Pre-filter.

**Мягкое удаление** — Пометка записи неактуальной вместо физического удаления (set_payload в Qdrant меняет метаданные, не трогая вектор). *(урок 2.4, 4.5)* См. также: Payload.

## Н

**Наблюдаемость** — Три столпа: логи (события), метрики (агрегаты), трейсы (путь запроса). Сервис обязан отдавать их о себе сам — «немой» сервис невозможно эксплуатировать. *(урок 3.7, 4.3)* См. также: Алерт, Кардинальность меток.

**НЕ-вызовы (тесты)** — Проверка, что дорогая зависимость НЕ вызывалась там, где не должна (LLM не звана при отбитом вводе). Требует фейков со счётчиками вызовов. *(урок 3.8, 5.7, 8.5)* См. также: Фейк.

## О

**Оркестратор** — Код, который решает, какой агент говорит следующим, что ему передать и когда остановиться. Судья, лимиты и ветка отказа всегда живут здесь. *(урок 7.2)* См. также: Мульти-агентная система, Судья-код.

**Отказ (канонический)** — Фиксированная формулировка «не могу ответить» («В документации ответа не нашёл»), которую можно детектировать кодом — по подстроке, не точным равенством. Отказ — фича, а не извинение. *(урок 3.4, 8.4)* См. также: Grounding.

**Отложенный набор** — Вопросы/примеры, которые модель не видела при обучении или настройке, — единственная честная основа для оценки. Eval на train — смертный грех. *(урок 1.7, 6.2)* См. также: Golden-набор.

## П

**Перекрытие (overlap)** — Дублирование хвоста чанка в начале следующего, чтобы мысль на границе целиком попала хотя бы в один из них. *(урок 2.5, 8.2)* См. также: Чанк.

**Переобучение (overfitting)** — Заучивание обучающих примеров вместо выучивания правила. Симптом: идеально на train, дословные чужие куски на новых вопросах. Лечение: меньше эпох/ранг, val-датчик. *(урок 6.2)* См. также: Отложенный набор, Ранг.

**Перцентиль (p50/p95/p99)** — Значение, ниже которого лежит N% замеров. Среднее лжёт: p95 показывает опыт «несчастливых» пользователей, из которых состоит репутация сервиса. *(урок 3.7, 4.3)* См. также: Алерт.

**Пирамида health-check** — Уровни проверки живости: L1 версия (дёшево), L2 списки/статусы, L3 настоящая генерация (дорого и деструктивно — грузит модель). Чем выше, тем реже. *(урок 5.5)* См. также: Liveness/Readiness.

**Пирамида тестов** — Много быстрых юнит-тестов, меньше интеграционных, немного e2e. В LLM-системах вершину заменяет eval на golden-наборе. *(урок 8.5)* См. также: Фейк, Golden-набор.

**Порог релевантности** — Минимальный score, ниже которого поиск считается неудачным. Калибруется на своих данных; не переносится между эмбеддерами и не ловит «уверенный мусор». *(урок 3.4, 8.3)* См. также: Косинусная близость.

**Права доступа (row-level)** — Фильтрация результатов поиска по правам ДО выдачи — pre-filter в векторной БД, а не пост-фильтрация. Инъекция и права — разные угрозы с разными рубежами. *(урок 4.5)* См. также: Pre-filter, Мультитенантность.

**Прогрев (warm-up)** — Первый «холостой» запрос после старта, поднимающий модель в память до включения трафика. Без него первый пользователь платит за холодный старт. *(урок 5.3, 8.6)* См. также: Холодный старт.

**Промпт** — Всё, что подаётся модели на вход: системная инструкция, история, контекст, вопрос. Инженерия промпта = управление вниманием модели. *(урок 1.2)* См. также: System prompt, Few-shot.

**Протечка стиля** — Дообученный (или SYSTEM-настроенный) стиль применяется к неуместным запросам — пингвин в ответе про код. Проверка общих навыков — обязательная часть приёмки. *(урок 6.3, 6.4)* См. также: Катастрофическое забывание.

## Р

**Ранг (LoRA r)** — Ширина матриц адаптера — «ёмкость» поправки. Для стиля хватает r=8–16; большой ранг на малом датасете = зазубривание. *(урок 6.1)* См. также: LoRA, Переобучение.

**Ретривер** — Поисковая половина RAG: по вопросу находит релевантные фрагменты. Оценивается отдельно от генератора (hit@k, MRR). *(урок 3.1, 3.3)* См. также: RAG, Hit@k.

**Роль (агента)** — Специализация LLM-вызова: свой системный промпт, бюджет токенов и фокус. Роли без проверяемого выхода — плата за ощущение надёжности. *(урок 7.1)* См. также: Мульти-агентная система.

## С

**Санитизация** — Очистка входных данных и документов от инъекций, невидимых символов, HTML-комментариев — с нормализацией (NFKC) до детекта. *(урок 3.7, 4.2)* См. также: Prompt injection.

**Семантический чанкинг** — Нарезка текста по «долинам» смысловой кривой (где соседние окна наименее похожи) вместо формальных границ. Требует эмбеддер уже на индексации. *(урок 2.6)* См. также: Чанк, Эмбеддинг.

**Стриминг** — Отдача ответа по мере генерации (SSE/NDJSON). Первый токен через доли секунды превращает «сервис завис» в «сервис печатает». *(урок 1.8, 3.2, 8.4)* См. также: SSE.

**Судья-код** — Валидация выхода агента исполняемой проверкой (тесты, схема, чекеры) вместо мнения LLM. Его нельзя убедить текстом, и он бесплатный. *(урок 7.2)* См. также: Оркестратор, LLM-судья.

## Т

**Телеметрия ответа** — Счётчики в ответе LLM-сервера (prompt_eval_count, eval_count, длительности) — бесплатный источник метрик скорости с каждого запроса. *(урок 5.5)* См. также: Наблюдаемость.

**Токен** — Единица, которой модель читает и пишет текст (кусочки слов). Токенами меряются контекст, цена и скорость; русский текст ~3–4 символа на токен. *(урок 1.1)* См. также: Контекстное окно.

**Троттлинг** — Снижение частот процессора/GPU при перегреве. На ноутбуках влияет на скорость генерации сильнее многих настроек — числа замеров всегда диапазоны. *(урок 5.2)*

## Ф

**Фейк (тестовый)** — Упрощённая реализация зависимости с тем же интерфейсом и счётчиками вызовов. Подменяется на границе (app.state), а не через monkeypatch. *(урок 3.8, 8.5)* См. также: НЕ-вызовы.

## Х

**Холодный старт** — Первый запрос после простоя платит за загрузку модели с диска в память (секунды–десятки секунд). Управляется keep_alive и прогревом. *(урок 5.3)* См. также: Прогрев, Keep_alive.

## Ч

**Чанк / чанкинг** — Фрагмент документа как единица индексации / процесс нарезки. Обе крайности плохи: крошки без контекста и «документ целиком» с размытым вектором. *(урок 2.5, 8.2)* См. также: Перекрытие, Контекстные заголовки.

## Ш

**Шаблон чата** — Разметка диалога, в которой модель обучена (для qwen — ChatML). Обязан совпадать при обучении и инференсе; в Ollama живёт в манифесте модели, не в GGUF. *(урок 1.6, 6.2, 6.3)* См. также: ChatML, Modelfile.

## Э

**Эмбеддинг** — Вектор фиксированной размерности, кодирующий смысл текста: близкие смыслы — близкие векторы. Основа семантического поиска. *(урок 2.1)* См. также: Косинусная близость, Дистрибутивная гипотеза.

**Эскалация (с чистого листа)** — Приём против якорения: после серии неудачных правок спрятать старое решение и передать только диагноз. Решение принимает код по счётчикам. *(урок 7.2)* См. также: Якорение.

## Я

**Якорение (anchoring)** — Залипание модели на собственном предыдущем ответе: правки косметические, суть не меняется. Главный враг циклов доработки. *(урок 7.2, 7.4)* См. также: Эскалация.

## A

**ADR (Architecture Decision Record)** — Полстраничная запись решения: контекст → решение → альтернативы → последствия. Раздел «Альтернативы» обязателен — иначе это пресс-релиз. *(урок 8.1)*

**ANN (Approximate Nearest Neighbors)** — Приближённый поиск ближайших векторов: жертвуем долей recall ради скорости на порядки. Индексы: IVF, HNSW. *(урок 2.2)* См. также: HNSW, Recall.

## B

**Base- и Instruct-модели** — Base продолжает текст (и не умеет диалог), Instruct дообучена следовать инструкциям в шаблоне чата. Перепутать — получить обрывки шаблона и done_reason=length. *(урок 1.6)* См. также: Шаблон чата.

**Bi-encoder** — Эмбеддер, кодирующий запрос и документ независимо: быстро (векторы документов посчитаны заранее), но грубее cross-encoder'а. *(урок 2.6)* См. также: Эмбеддинг, Cross-encoder.

**BM25** — Классический лексический скоринг (эволюция TF-IDF): точные совпадения строк, версии, IP-адреса — то, что эмбеддинги размывают. *(урок 4.4)* См. также: Гибридный поиск, RRF.

## C

**C4-диаграмма** — Архитектура уровнями зума: контекст → контейнеры → компоненты (→ код). Каждый уровень отвечает на свой вопрос «кто с кем». *(урок 8.1)*

**Chain-of-Thought (CoT)** — Приём «сначала рассуждение, потом ответ». Для маленьких моделей надёжнее в жёсткой форме: чеклист с полями вместо свободных размышлений. *(урок 1.7, 7.1)*

**ChatML** — Шаблон чата семейства qwen: <|im_start|>role ... <|im_end|>. Собирается сервером из messages — руками его писать нужно только чтобы понимать, чему учим. *(урок 1.6, 6.2)* См. также: Шаблон чата.

**Cross-encoder** — Модель, читающая пару «запрос+документ» одним проходом: точнее bi-encoder'а, дороже — O(кандидатов). Вторая ступень поиска. Шкала — логиты, не косинусы. *(урок 2.6, 4.4, 8.3)* См. также: Reranking, Bi-encoder.

## D

**Debate (паттерн)** — Несколько мнений об одном решении + судья. Работает за счёт дистанции и узкого фокуса критика; слабое звено — судья (лечится чеклистом). *(урок 7.1)* См. также: Мульти-агентная система.

**Digest (модели)** — Криптографический отпечаток точных весов. Теги мутабельны (qwen2.5:3b завтра — другие веса), digest — нет. Адаптеры и пороги привязаны к digest. *(урок 5.6)* См. также: Канарейка, Адаптер (LoRA-).

**done_reason** — Поле ответа Ollama: почему генерация остановилась. stop — модель закончила сама, length — упёрлась в num_predict (ответ обрезан!). *(урок 1.6, 5.2)* См. также: Num_predict.

## E

**E5 (префиксы query:/passage:)** — Семейство эмбеддеров, обученных с префиксами ролей текста. Без префиксов качество тихо проседает — это контракт модели, а не украшение. *(урок 2.1)* См. также: Эмбеддинг.

**Eval** — Измеримая оценка качества на фиксированном наборе. Первый шаг любого улучшения: без eval оптимизация — это мода, а не инженерия. *(урок 1.7, 3.3)* См. также: Golden-набор, LLM-судья.

## F

**Faithfulness** — Верность ответа контексту: каждое утверждение подтверждается источником. Проверяется LLM-судьёй по атомарным фактам. *(урок 3.3)* См. также: Grounding, LLM-судья.

**Few-shot** — Примеры «вход → выход» прямо в промпте. Подсказывает форму, но не обязывает: платится токенами на каждый запрос, стиль плавает. *(урок 1.7, 6.1)* См. также: Zero-shot, Промпт.

**Function calling** — Протокол вызова инструментов: модель генерирует JSON с именем и аргументами, исполняет — ваш код, результат возвращается ролью tool. *(урок 3.5)* См. также: Инструмент.

## G

**GBNF-грамматика** — Формальная грамматика llama.cpp, жёстко ограничивающая выход модели. Умеет запрещать, но не подсказывать: без подводки в промпте даст мусор в разрешённой форме. *(урок 5.4)* См. также: Structured output.

**GGUF** — Формат упакованных весов llama.cpp: одна квантованная модель одним файлом. Блоб в хранилище Ollama — это готовый GGUF. *(урок 5.2, 5.4, 6.3)* См. также: Квантизация, Modelfile.

**Golden-набор** — Эталонные вопросы с ожидаемыми ответами/источниками для регрессионного eval. Вырастает из реальных вопросов пользователей — поэтому историю копят с первого дня. *(урок 3.3, 8.6)* См. также: Eval, Отложенный набор.

**GQA (Grouped-Query Attention)** — Архитектурная экономия: KV-голов меньше, чем Q-голов (у qwen2.5:3b — 2 против 16). Меньше KV-кэш и — приятный бонус — дешевле LoRA на k/v. *(урок 5.2, 6.1)* См. также: KV-кэш.

**Grounding** — Требование отвечать только фактами из предоставленного контекста, с честным отказом при их отсутствии. Ядро надёжного RAG. *(урок 3.1, 3.4)* См. также: Отказ, Faithfulness.

## H

**Hit@k** — Доля вопросов, для которых правильный документ попал в топ-k выдачи. Метрика ретривера, не зависящая от генератора. *(урок 3.3)* См. также: MRR, Ретривер.

**HNSW** — Граф «малого мира» для ANN: жадный спуск по слоям от дальних связей к ближним. Отгадка скорости современных векторных БД. *(урок 2.2)* См. также: ANN.

## K

**Keep_alive** — Сколько Ollama держит модель в памяти после запроса (дефолт 5 минут). Ноль — выгрузить немедленно; за простой платит следующий запрос холодным стартом. *(урок 5.3)* См. также: Холодный старт.

**KV-кэш** — Память под ключи/значения внимания для всего контекста. Растёт с num_ctx (у 3B ~39 КБ на токен) и умножается на параллельные слоты. *(урок 5.6)* См. также: Контекстное окно, GQA.

## L

**Liveness / Readiness** — Две разные пробы: «процесс жив» (без внешних проверок — иначе каскадные рестарты) и «готов принимать трафик» (зависимости доступны). *(урок 5.5, 8.5)* См. также: Пирамида health-check.

**LLM (Large Language Model)** — Нейросеть, предсказывающая следующий токен, — и оказавшаяся от этого универсальным текстовым интерфейсом. Вся её «память» — веса плюс контекст. *(урок 1.1)* См. также: Токен.

**LLM-судья** — Использование модели для оценки ответов. Надёжен только в узкой форме: бинарные да/нет по одному факту/кандидату, с вопросом после фрагмента; любого судью калибруют. *(урок 3.3, 7.2)* См. также: Eval, Судья-код.

**LoRA (Low-Rank Adaptation)** — Дообучение поправкой W + (alpha/r)·B·A к замороженным весам: <1% обучаемых параметров. B инициализируется нулями — старт с нетронутой модели. *(урок 6.1)* См. также: Адаптер (LoRA-), Ранг, QLoRA.

## M

**Modelfile** — «Dockerfile для модели» в Ollama: FROM (веса/база), TEMPLATE (шаблон чата — из GGUF сам не приедет!), SYSTEM, PARAMETER, ADAPTER. *(урок 6.3)* См. также: GGUF, Шаблон чата.

**MRR (Mean Reciprocal Rank)** — Средний обратный ранг первого правильного результата: 1-е место = 1, 2-е = 0.5. Чувствительнее hit@k к порядку выдачи. *(урок 3.3)* См. также: Hit@k.

## N

**Num_ctx** — Размер контекстного окна в Ollama. Больше окно — больше KV-кэш: +30 тысяч токенов у 3B стоят ~1.2 ГБ памяти. *(урок 5.6)* См. также: KV-кэш.

**Num_predict** — Потолок токенов ответа — стоп-кран против бесконечной генерации. В проде обязателен на каждом запросе; на сервере ему положен свой потолок. *(урок 5.6, 5.7)* См. также: done_reason.

## P

**Payload (Qdrant)** — JSON-метаданные точки: источник, права, версия. По ним работают фильтры внутри HNSW-обхода — при объявленных payload-индексах. *(урок 2.4, 4.5)* См. также: Pre-filter.

**Pipeline (паттерн)** — Роли по очереди: выход одной — вход следующей. Для известного маршрута; ошибка ранней роли едет по конвейеру дальше — валидируйте на стыках. *(урок 7.1)* См. также: Supervisor, Мульти-агентная система.

**Pre-filter / post-filter** — Фильтрация во время поиска против фильтрации результатов после. Post-filter на строгих условиях оставляет пустую выдачу — «проклятие post-фильтра». *(урок 2.2, 4.5)* См. также: Payload.

**Prefill / decode** — Две фазы генерации: параллельное прочтение промпта (сотни-тысячи ток/с) и последовательная генерация (десятки). Меряются отдельно; повторные промпты кешируются. *(урок 1.5, 5.2)* См. также: Телеметрия ответа.

**Prompt injection** — Атака инструкциями внутри данных (вопроса или документа): «забудь правила и...». Рубежи: санитизация, изоляция данных разметкой, output-guard, права. *(урок 1.2, 4.2)* См. также: Санитизация.

## Q

**QLoRA** — LoRA поверх базы, квантованной в 4 бита (NF4): обучение 3B помещается в ~4 ГБ VRAM. Merge адаптера делается в fp16, а не в 4-битные веса. *(урок 6.1, 6.3)* См. также: LoRA, Квантизация.

## R

**RAG (Retrieval-Augmented Generation)** — Поиск релевантных фрагментов + генерация ответа по ним. Знания живут в индексе (обновляются переиндексацией), а не в весах. *(урок 3.1)* См. также: Ретривер, Grounding.

**RAGAS** — Библиотека готовых RAG-метрик. Урок курса: чужого судью калибруют так же, как своего — на русском с маленькой моделью может молча выдавать нули. *(урок 3.3)* См. также: Eval.

**Recall / precision (поиска)** — Полнота (ничего не упустить — широкая сеть кандидатов) против точности (не тащить мусор — вторая ступень). Двухступенчатая схема разводит их по этапам. *(урок 4.4, 8.3)* См. также: Reranking.

**Reranking** — Пересортировка кандидатов первой ступени более точной моделью (cross-encoder, LLM-судья). Порог применяют ПОСЛЕ реранка, невод первой ступени — широкий. *(урок 2.5, 2.6, 4.4)* См. также: Cross-encoder.

**RRF (Reciprocal Rank Fusion)** — Слияние выдач разных поисков по рангам (1/(k+ранг)), без сравнения несравнимых score. Стандарт для гибридного поиска. *(урок 4.4)* См. также: Гибридный поиск.

## S

**SSE (Server-Sent Events)** — Протокол стриминга поверх HTTP: события event:/data: с пустой строкой-разделителем. Ошибки после старта потока передаются событием — статус уже ушёл. *(урок 3.2, 8.4)* См. также: Стриминг.

**Structured output** — Принуждение модели к формату: грамматики, format=json, схемы. Дообучение повышает вероятность формата, грамматика делает её единицей. *(урок 5.4, 6.2)* См. также: GBNF-грамматика.

**Supervisor (паттерн)** — LLM-диспетчер разбирает задачу на подзадачи и раздаёт исполнителям. Оправдан, когда декомпозиция зависит от входа; иначе — дорогой pipeline. *(урок 7.1)* См. также: Pipeline.

**System prompt** — Инструкция роли, приходящая раньше пользовательского ввода и имеющая приоритет. В Ollama может жить в Modelfile — и тогда оплачивается prefill'ом каждого запроса. *(урок 1.2, 6.3)* См. также: Промпт.

## T

**Temperature** — Степень случайности выбора токенов: 0 — почти детерминированно (но не бит-в-бит на GPU), выше — разнообразнее. Для grounding и форматов держат низкой. *(урок 1.2, 3.3)*

**TF-IDF** — Классический лексический скоринг: частота слова в документе × редкость в корпусе. Наш «поиск без нейросетей» и вечная линия сравнения. *(урок 2.5)* См. также: BM25.

**Train_on_responses_only** — Маскирование вопросов из loss при дообучении диалогов: штраф начисляется только за токены ответа — иначе модель учится писать вопросы. *(урок 6.2)* См. также: Дообучение (fine-tuning).

## U

**Upsert** — Вставка-или-обновление по ID. С детерминированными ID делает индексацию идемпотентной; хвост-ловушка: укоротившийся документ оставляет точки-сироты. *(урок 2.3, 2.4)* См. также: Идемпотентность, uuid5.

**uuid5** — Детерминированный UUID из строки (namespace + имя): те же входные данные — тот же ID. Основа идемпотентного upsert'а. *(урок 2.4, 8.2)* См. также: Upsert.

## Z

**Zero-shot** — Запрос без примеров: только инструкция. Первая ступень лестницы приёмов — и удивительно часто достаточная. *(урок 1.7)* См. также: Few-shot.
