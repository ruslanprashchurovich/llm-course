# Модуль 4. Продвинутый RAG: надёжность, безопасность и контроль в продакшене

Учебный модуль курса «LLM для Python-разработчиков: от RAG до агентов».

В модуле 3 вы собрали работающий RAG-сервис. Здесь мы делаем его **пригодным
для продакшена**: учимся видеть, как он тихо деградирует, защищаем его от
атак через документы, оснащаем наблюдаемостью, улучшаем качество поиска и
раздаём права доступа. Сквозной пример прежний — база знаний вымышленной
компании **«Векторика»**, но корпус подрос: теперь в нём есть **две версии**
одного документа, **конфиденциальные** зарплатные вилки, **постмортем с ПДн**
и специально **отравленный** community-документ.

**Всё бесплатно и локально.** LLM — `qwen2.5:3b` в Ollama, векторная база —
Qdrant в Docker, эмбеддер по умолчанию — свой **TF-IDF без скачиваний**
(нейроэмбеддер e5 и cross-encoder — опционально, в уроке 4.4).

## Чему вы научитесь

- **Диагностировать** пять антипаттернов продового RAG: устаревшие данные,
  плохой чанкинг, нерелевантный поиск, длинный контекст, тихие сбои.
- **Защищать** RAG на каждом рубеже: санитизация документов, детект prompt
  injection, маскирование ПДн, укреплённый промпт, контроль ответа.
- **Наблюдать** сервис: структурные логи с `trace_id`, метрики Prometheus,
  трейсинг стадий, алерты.
- **Улучшать поиск**: reranking (cross-encoder), слияние RRF, multi-query.
- **Разграничивать доступ**: фильтрация по правам, мультитенантность,
  версионирование документов.

## Общий пакет `rag_service/`

В отличие от модуля 3 (где код рос от урока к уроку), модуль 4 с самого начала
опирается на единый пакет — как настоящий сервис. Уроки включают и выключают
его части.

```
rag_service/
├── config.py         # настройки из env (127.0.0.1, TF-IDF по умолчанию)
├── embeddings.py     # TF-IDF (по умолчанию) / e5 (опц.) за одним интерфейсом
├── store.py          # Qdrant: коллекция, payload-индексы, фильтры, upsert
├── ingest.py         # ETL индексации: санитизация → чанкинг → эмбеддинги → Qdrant
├── security.py       # детект injection, нормализация, маскирование ПДн, output guard
├── access.py         # Principal и фильтр прав (row-level security)
├── prompts.py        # наивный и укреплённый промпты (nonce, canary)
├── llm.py            # клиент Ollama + оффлайн-заглушка StubLLM
├── retrieval.py      # dense + BM25 + RRF (+ rerank, multi-query)
├── pipeline.py       # полный путь запроса: рубежи обороны по порядку
├── observability.py  # JSON-логи, метрики Prometheus, трейсинг стадий
└── app.py            # FastAPI: /ask, /healthz, /metrics, авторизация по токену
```

## Что понадобится

- **Python 3.13** (подойдёт 3.12).
- **Docker Desktop** — для Qdrant.
- **Ollama** с моделью: `ollama pull qwen2.5:3b`.

### Установка (Windows PowerShell)

```powershell
cd C:\Users\<вы>\ml_projects\llm-course\04-advanced-rag
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Запуск базы и индексация

```powershell
docker compose up -d
python -m rag_service.ingest --reset
```

Индексация прочитает `data/manifest.json`, санитизирует документы, порежет на
чанки и зальёт в Qdrant. В типовом прогоне: **12 документов → 25 чанков**,
попутно маскируются ПДн (EMAIL, PHONE, CARD, INN) и помечается отравленный
документ.

### Запуск сервиса

```powershell
uvicorn rag_service.app:app --host 127.0.0.1 --port 8004
```

```bash
curl -X POST http://127.0.0.1:8004/ask ^
  -H "Content-Type: application/json" ^
  -H "X-API-Token: demo-employee-token" ^
  -d "{\"question\": \"Сколько дней отпуска в 2026?\"}"
```

Токены-демо: `demo-employee-token` (общий доступ), `demo-hr-token` (видит
зарплаты и ПДн), `demo-engineer-token` (инженерные документы),
`demo-other-tenant-token` (чужой арендатор — не видит ничего).

## Про данные

`data/manifest.json` — сердце модуля. У каждого документа есть метаданные,
на которых строятся уроки:

- `version` + `is_current` — две редакции отпуска (урок 4.1: устаревшие данные);
- `sensitivity` (0/1/2) + `department` — уровни доступа (уроки 4.2, 4.5);
- `source_type` (`trusted`/`untrusted`) — доверие к источнику (урок 4.2);
- отравленный `12-faq-vpn-community.txt` — живая атака prompt injection.

## Частые проблемы

- **`localhost` тормозит на Windows.** httpx сначала пробует IPv6 `::1` и теряет
  ~2 секунды на соединение. Все дефолты в `config.py` — `127.0.0.1`.
- **Коллекция пустая / размерность не сходится.** TF-IDF учит словарь на
  корпусе, поэтому при переиндексации коллекция **пересоздаётся** под новую
  размерность (`ingest --reset`). Это нормально.
- **Порог релевантности «не тот».** Порог не переносится между эмбеддерами:
  для TF-IDF годные скоры ~0.15–0.45, для e5 — ~0.75–0.90 (урок 3.4).
- **Медленный первый ответ.** Холодный старт Ollama: первый вызов грузит модель
  в память (десятки секунд), дальше — секунды (разбор в уроке 4.3).
