Тестирование и качество кода

Мы придерживаемся пирамиды тестов: много быстрых unit-тестов, меньше интеграционных, немного end-to-end. Unit-тесты пишутся вместе с кодом и обязательны для новой бизнес-логики. Минимальное покрытие для новых модулей — 80% строк, проверяется в CI.

Тесты запускаются автоматически на каждый merge request. Красный пайплайн блокирует слияние — чинить тесты обязан автор изменений. Флаки-тесты (нестабильные) помечаются меткой flaky и должны быть исправлены в течение двух недель, иначе удаляются.

Интеграционные тесты используют testcontainers: PostgreSQL и Redis поднимаются в Docker на время прогона. E2E-тесты гоняются ночью на staging, отчёт приходит в канал #qa-reports.

Ручное тестирование выполняется QA-инженером только для крупных фич по чек-листу из задачи.
