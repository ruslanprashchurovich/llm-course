# kb-search — поиск по базе знаний «Векторики»

Финальный проект модуля 2: CLI-утилита поверх всего арсенала модуля — чанкинг с контекстными заголовками (по абзацам или по смысловой кривой), метаданные, pre-filter по темам, диверсификация выдачи, parent-window, вторая ступень (cross-encoder / LLM-судья), встроенный eval со сравнением бэкендов и снапшоты Qdrant. Два взаимозаменяемых бэкенда за одним интерфейсом.

## Бэкенды

| | `lexical` | `semantic` |
|---|---|---|
| скоринг | TF-IDF (уроки 2.5–2.6) | e5-эмбеддинги + косинус (урок 2.1) |
| хранилище | `index_lexical.json` рядом | Qdrant (урок 2.4) |
| зависимости | нет (stdlib + utils) | sentence-transformers, qdrant-client, запущенный Qdrant |
| понимает синонимы | нет («Упал прод» не найдётся) | да |

По умолчанию (`--backend auto`) утилита сама выбирает semantic, когда модель в кэше и Qdrant отвечает, — иначе честно работает на lexical и говорит об этом.

## Команды

```bash
# диагностика: данные, Qdrant, модель, индекс
python project/kb_search.py health

# построить индекс (чанкует data/, добавляет контекстные заголовки)
python project/kb_search.py index

# индексация по смысловой кривой (урок 2.6, акт 2; нужна e5 в кэше)
python project/kb_search.py index --chunking semantic

# поиск
python project/kb_search.py search "Сколько доплачивают за болезнь?"
python project/kb_search.py search "Куда писать про сломанный ноутбук?" --topic it
python project/kb_search.py search "Как оформить больничный и отпуск?" --diverse --top 5

# больше контекста: окно +-300 символов вокруг находки или родитель целиком
python project/kb_search.py search "Сколько доплачивают за болезнь?" --parent
python project/kb_search.py search "Сколько доплачивают за болезнь?" --parent full

# вторая ступень: cross-encoder (нужен в кэше) или LLM-судья (нужна Ollama)
python project/kb_search.py search "Упал прод, что делать?" --rerank ce
python project/kb_search.py search "Упал прод, что делать?" --rerank llm

# встроенный eval: 7 вопросов, top-1/top-3, размер находки
python project/kb_search.py eval
python project/kb_search.py --backend lexical eval

# один eval — оба бэкенда: таблица-сравнение вместо впечатлений
python project/kb_search.py compare

# снапшот коллекции Qdrant через API (wait=False + поллинг готовности)
python project/kb_search.py backup
```

Запускать из папки модуля `02-embeddings-vector-db` (утилита сама найдёт `data/` и `utils.py` относительно себя, так что можно и из `project/`).

## Какие уроки где работают

| место в коде | урок |

| `build_chunks` — абзацный чанкинг + контекстные заголовки, паспорт чанка | 2.5, 2.6 |
| `LexicalBackend` — TF-IDF со всеми его пределами | 2.5 |
| `SemanticBackend` — e5-префиксы, uuid5-id, payload-индекс, query_points | 2.1, 2.4 |
| `topic` как pre-filter, а не post | 2.2, 2.4 |
| `rerank_diverse` — вторая ступень | 2.5 |
| `cmd_eval` — метрики вместо впечатлений | 1.7 |
| `split_semantic` — границы по «долинам» смысловой кривой (`--chunking semantic`) | 2.6, акт 2 |
| `parent_window` — окно ±300 символов вокруг находки (`--parent`) | 2.6, решение 2 |

| `cmd_backup` — снапшот Qdrant: `wait=False` + поллинг | 2.4 |

## Задания для прокачки (из урока 2.7)

Все пять пунктов реализованы в `kb_search.py` как эталон — но порядок работы прежний: **сначала попробуйте сами**, не подглядывая, потом сравните подходы. По возрастанию сложности:

1. **`compare`** — команда, гоняющая eval на обоих бэкендах и печатающая таблицу-сравнение (после скачивания e5 — самая показательная команда утилиты: на «Упал прод» lexical мимо, semantic находит).
2. **`--parent`** — флаг для `search`: отдавать родительский документ (`--parent full`) или окно ±300 символов вокруг находки (урок 2.6, решение 2 — почти готовый код).
3. **`--chunking semantic`** — альтернативная стратегия индексации для владельцев e5 (урок 2.6, акт 2): границы по долинам смысловой кривой. На нашей базе даёт 42 чанка вместо 31 при том же качестве eval — стратегию имеет смысл выбирать по eval, а не по красоте идеи.
4. **`backup`** — снапшот коллекции Qdrant через API (урок 2.4; помните `wait=False` и терпение на Windows: на нашей машине снапшот строился ~40 секунд). Файл живёт внутри контейнера — скачивайте его по `GET`-ссылке, которую печатает команда.
5. **`--rerank`** — вторая ступень: cross-encoder (`ce`, урок 2.6; модель нужно скачать один раз, ~500 МБ) или LLM-судья (`llm`, Ollama из модуля 1). Если модели нет — утилита честно предупреждает в stderr и показывает выдачу первой ступени. Грабли из живого прогона: батч-промпт со шкалой 0–10 (решение 3 урока 2.6) у 3B-судьи разваливается — работает только **бинарное да/нет по одному кандидату** с вопросом **после** фрагмента (см. `build_judge_prompt`; та же история всплывёт в уроке 3.3).
