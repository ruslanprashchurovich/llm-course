# Модуль 7. Мульти-агентные системы: оркестрация и роли

Часть курса «LLM для Python-разработчиков: от RAG до агентов».

В уроке 3.5 агент был один — модель с инструментами в цикле. Этот модуль про
**команды**: несколько LLM-ролей, оркестратор, который двигает между ними работу,
и честная цена всего этого. Сквозной пример — команда «аналитик → разработчик →
ревьюер» хостинга «Пингвин.Хост» 🐧, которая пишет настоящий код, принимаемый
настоящими тестами.

Модуль намеренно построен на **маленькой локальной модели** (qwen2.5:3b):
её ограничения в агентных сценариях — не помеха курсу, а его материал. Все
приёмы борьбы (жёсткие форматы, валидация выходов кодом, лимиты, эскалация)
показаны на живых прогонах, включая неудачные.

## Цели модуля

После прохождения вы сможете:

- Решать, когда нужна команда агентов, а когда один агент лучше (и дешевле).
- Различать паттерны pipeline / supervisor / debate и их цену.
- Строить оркестратор на чистом Python: сообщения, журнал, роли, судья-код,
  фикс-циклы с лимитами, эскалация, честный отказ.
- Собирать ту же команду на CrewAI с локальной LLM — и понимать, что фреймворк
  делает за вас, а что всё равно останется вашей работой.
- Валидировать выходы агентов кодом и проектировать читаемые отчёты для LLM-ревью.

## Подготовка окружения для уроков 7.3–7.4

Агентные фреймворки (CrewAI, LangGraph, AutoGen) тянут десятки зависимостей —
изолируем их в venv прямо в папке модуля:

```powershell
cd C:\Users\rusla\ml_projects\llm-course\07-multi-agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install "protobuf>=6.33"   # вторым шагом - почему, объясняет урок 7.4
python -m ipykernel install --user --name crewai-course --display-name "Python (crewai)"
```

и выберите ядро «Python (crewai)» в Jupyter для ноутбуков уроков 3 и 4. На Windows
держите venv в коротком пути (как здесь): глубоко вложенные папки упираются
в лимит длины пути при установке зависимостей CrewAI.

## Практика урока 7.4: эталоны в проекте

Финальная практика остаётся вашим проектом, но эталоны всех трёх заданий лежат в
`agent-team/` — сверяйтесь после своей попытки (подробности в README внутри):

- **Задание 1, полный автомат на LangGraph:** `team/graph.py` (analyst → developer →
  tester → tracer → fixer → escalate → finish, флаг `escalated` в состоянии) и
  `team/imperative.py` (оркестратор 7.2 на тех же промптах); тест
  `test_imperative_vs_graph.py` требует совпадения журналов узел в узел.
- **Задание 2, supervisor по-настоящему:** `team/supervisor.py` — AutoGen
  `SelectorGroupChat`, отдельный счётчик токенов selector'а, доля «не тех» выборов
  против политики конвейера, режимы `selector | policy | roundrobin`, критик-судья.
- **Задание 3, капстоун:** `team/triage.py` — триаж тикетов с судьёй-кодом (схема +
  заземление + правила), eval на 12 тикетах, команда против одиночки, выдача через
  `ollama-proxy` (`TEAM_BACKEND=proxy`).
- Всё гоняется в обычном окружении курса (`ml_env`): `pip install -r agent-team/requirements.txt`,
  для задания 2 — AutoGen двумя шагами (см. комментарий в requirements). Оффлайн-тесты:
  `cd agent-team && pytest` — 56 тестов без Ollama (без AutoGen один помечается skip).

## Честные ориентиры из живых прогонов

- Debate на «тикете-крике»: классификатор ставит high, наивный судья копирует,
  судья с чеклистом выносит low. Цена решения — 4 вызова и ~1100 токенов
  против 1 вызова и ~200.
- Команда 7.2 на normalize_phone: 11 вызовов, ~70 секунд — и честный
  «REJECTED: нужен человек»; человек с журналом чинит одну строчку за минуту,
  приёмка 6/6. В части прогонов команда добегает до 6/6 сама — грань у 3B плавает.
- CrewAI: тот же конвейер в ~40 строк, но 4 запроса и ~1870 токенов промптов
  на 2 задачи (обвязка), а приёмка кода — по-прежнему ваша забота.
- LangGraph: конечный автомат 7.2 переложился в StateGraph узел-в-узел; сходимость
  не изменилась (3 попытки → «нужен человек») — её определяет модель, а не синтаксис.
- AutoGen: диалог «писатель ↔ критик» остановился по стоп-слову за 2 хода — но
  критик-3B одобрил уведомление без требуемого извинения: в чате некуда воткнуть
  судью-код.
- Практика 7.4 (`agent-team/`, прогоны на qwen3.5:9b — см. README внутри): граф
  LangGraph и оркестратор 7.2 дали одинаковый журнал узел в узел; у AutoGen
  SelectorGroupChat два решения «кто следующий» стоили 1173 токена — 65 % всего
  расхода, и selector пропустил аналитика; на триаже 12 тикетов команда выиграла
  у одиночки только приоритетом (75 % против 50–58 %) за ×1.5 токенов, а через
  ollama-proxy с лимитом 6/мин получила два 429 и честно подождала Retry-After.

## FAQ

**Нужна ли модель побольше?** Для прохождения — нет: все уроки живут на 3B, и её
провалы — часть материала. Если у вас есть 7B+ — повторите прогоны и сравните
сходимость фикс-циклов (это упражнение само по себе).

**Почему код агентов запускается через subprocess?** Код, написанный LLM, —
недоверенный (урок 4.2): отдельный процесс с таймаутом защищает ноутбук от
вечных циклов и случайных глупостей. В проде это делается в контейнере.

**CrewAI падает с RuntimeError про event loop.** Вы зовёте `crew.kickoff()`
из Jupyter — используйте `await crew.kickoff_async()` (в ноутбуках работает
верхнеуровневый await). У AutoGen `team.run(...)` асинхронный по природе —
в ноутбуке тоже просто `await`.

**После pip install импорт падает: «DLL load failed... Политика управления
приложениями заблокировала этот файл».** Windows (Smart App Control) не доверяет
свежескачанным нативным библиотекам — pip сохраняет на них «метку интернета».
Лечение из PowerShell:
`Get-ChildItem .venv -Recurse -Filter *.pyd | Unblock-File`
