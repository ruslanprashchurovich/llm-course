# Капстоун 6.4: JSON-бот «Пингвин.Хост» от и до

Эталонное решение задания 3 финальной практики модуля 6 — сначала попробуйте
сами, потом сверяйтесь. Задача из упражнений 6.1 (3б), 6.2 (3) и 6.3 (2):
бот-техписатель, который на **любой** вопрос отвечает строго одним JSON

```json
{"answer": "Резервные копии создаются автоматически раз в сутки и хранятся 14 дней.", "confidence": 0.96}
```

и честно отказывается на вопросы не по теме: `{"answer": null, "confidence": 0.0}`.

## Конвейер (тот же, что у Пингвина в уроках 6.2–6.3)

```
make_dataset.py ──▶ data/train_messages.jsonl (+val, +test)
                        │
   colab-train-lora.ipynb с TASK = "json" (загрузить оба jsonl, T4, ~10-15 мин)
                        │
   artifacts/pingvin-json-q4_k_m.gguf ──▶ ollama create pingvin-json -f Modelfile.pingvin-json
                        │
   acceptance.py ──▶ PASS/FAIL ──▶ ollama-proxy (PROXY_MODEL=pingvin-json)
```

### 1. Датасет: 500+ примеров одной командой

```bash
python capstone/json_bot/make_dataset.py
```

Скрипт генерирует данные из закрытой базы знаний (40 фактов о хостинге, 8 «частично
знакомых» тем, 10 пустых вопросов, 25 категорий не по теме) и печатает статистику.
Четыре решения, которых не видно в формулировке задания:

| Решение | Почему |
|---|---|
| **Одна confidence на факт**, одинаковая для всех его перефразировок | уверенность — свойство знания, а не формулировки; иначе модель выучит «вежливый вопрос = уверенный ответ» |
| **~30 % отказов** `null / 0.0` | без них бот уверенно отвечает на всё (эскиз решения 3 в уроке 6.2) |
| **Мутации формулировок** (префиксы, регистр, без пунктуации) | 500 примеров нужны ради устойчивости формата, а не ради знаний |
| **Отложенный экзамен не пересекается с обучением** (скрипт это проверяет) | иначе приёмка измеряет зазубривание |

Val (30 примеров) стратифицирован по видам — в нём есть и отказы, поэтому
val-loss честно отражает и формат, и калибровку.

### 2. Обучение

В `colab-train-lora.ipynb` поставьте `TASK = "json"` (ШАГ 2) и загрузите
`capstone/json_bot/data/train_messages.jsonl` и `val_messages.jsonl`. На ~500
примерах достаточно 3 эпох (~190 шагов при батче 8): ответы короткие, формат
жёсткий. Смоук-тест ноутбука для этой задачи проверяет не якоря, а `json.loads`.

### 3. Импорт и приёмка

```bash
ollama create pingvin-json -f capstone/json_bot/Modelfile.pingvin-json
python capstone/json_bot/acceptance.py pingvin-json
python capstone/json_bot/acceptance.py pingvin-json --format-json
```

`style_score` здесь — пять проверок формата и смысла (JSON парсится, без прозы,
ровно два ключа, правильные типы, смысл по виду вопроса), PASS — 90 % идеальных
ответов и ноль прозы. Второй прогон с `--format-json` включает грамматику Ollama:
она гарантирует валидный JSON, но не чинит калибровку и отказы — сравните два
вердикта и увидите, что именно дало дообучение (урок 5.4: грамматика умеет
запрещать, а не подсказывать).

Для картины «до» прогоните приёмку на базе: `acceptance.py qwen2.5:3b --limit 8`.

### 4. Наружу через прокси (урок 5.7)

```powershell
$env:PROXY_MODEL = "pingvin-json"
uvicorn app.main:app --host 127.0.0.1 --port 8005     # из 05-local-llm/ollama-proxy
```

```bash
curl -X POST http://127.0.0.1:8005/generate -H "X-API-Token: dev-token" \
  -H "Content-Type: application/json" -d '{"prompt": "Как часто делаются бэкапы?", "num_predict": 100}'
```

Прокси добавит то, чего у модели нет: auth, лимит на токен, потолок `num_predict`,
метрики и деградацию на запасную модель. Модель со своим характером плюс
прод-обвязка — курс сошёлся.

## Честные ограничения

- Факты зашиты в веса только потому, что набор закрытый и маленький. В проде
  знания живут в RAG (модуль 3), а дообучение отвечает за формат и калибровку.
- Confidence из дообучения — выученная привычка, а не вероятность: на вопросах
  вне обучающего распределения она может быть уверенно неверной. Калибровку
  проверяйте своим eval'ом (урок 3.3).
- Датасет синтетический: реальные вопросы клиентов грязнее. Первые 100 живых
  тикетов стоит добавить в `FACTS`/`OFF_TOPIC` и переобучить.
